# NFL Player Selector 1.0.0

Released September 20, 2026. The first stable release of the weekly NFL touchdown-pool
workflow, distributed as a Python wheel and source archive on GitHub.

## What's included

- `pool week` refreshes stale data and shows what to submit, hold, or revisit, with
  deadlines, alternatives, previous advice, and commands for recording submitted picks.
- Record and correct historical picks, import and validate official pool reports, and
  read personal scores and standings through shared touchdown accounting.
- Back up the database and export picks without overwriting existing files. Backups
  publish a verified copy using a unique temporary file and refuse destination races.
- Capture decisions and submissions with package fingerprints and runtime dependency
  versions, including when the CLI is installed outside a source checkout.
- Archive rival rankings and simulated distributions independently, retry partial save
  failures, and continue refreshing until touchdown coverage and feeds are settled.
- Copyable follow-up commands retain the chosen database, season, and applicable week,
  quote shell arguments, and remain on one output line.
- Separate `pool research` commands provide replays, evaluation, calibration, and capture
  verification. Expected pot share remains an experimental view beside expected-TD advice.

## Install and upgrade

Python 3.11 or newer is required; development and CI use Python 3.12. With uv installed,
install the release wheel directly:

```bash
uv tool install https://github.com/ckloote/nfl-player-selector/releases/download/v1.0.0/nfl_pool-1.0.0-py3-none-any.whl
pool --help
```

For an existing uv tool installation, use the same command with `--force` to replace it.
For a source checkout, switch to tag `v1.0.0` and run `uv sync --locked`.

Keep a database backup before upgrading. Set `POOL_DB` to an absolute path, or pass
`--db`, when running from different directories: the default `data/pool.db` is relative
to the working directory. This release preparation changes package version and
release documentation only; it adds no migration or runtime dependency.

## Known limitations

- **Standings presentation:** wide tables can truncate names and headings at normal
  terminal widths. A compact summary and separate detail view are deferred.
- **Legacy PIT commitments:** restored databases containing unfrozen schema-1 commitments
  still reconstruct outcomes with the sampler installed when first scored. Runtime
  compatibility checks and migration hardening are deferred. Compatibility after a
  sampler/environment change is not guaranteed for these records. New commitments store
  their outcomes; an existing freeze receipt preserves already-frozen legacy outcomes.
- **Experimental pot share:** simulation and opponent-model calibration have documented
  limits, including same-team substitution. Version 1.0 does not establish that the policy
  wins pools or promote a new prediction model.
- **Research execution:** reproducible studies still require a source checkout and their
  archived inputs. Installing the wheel supports the weekly CLI, not a self-contained
  research dataset. Live results depend on feed availability and complete touchdown data.

## Verification

The release is gated by the existing lint, formatting, and full pytest CI job and the
separate wheel-install job. The latter installs the wheel and runtime dependencies into
an isolated environment, checks distribution metadata and the installed entry point,
and records and reads a synthetic historical pick and its captured identity from outside
the checkout. Verification uses disposable data and no live feed downloads.

See the [CI runs](https://github.com/ckloote/nfl-player-selector/actions/workflows/ci.yml)
and [project review](https://github.com/ckloote/nfl-player-selector/blob/v1.0.0/docs/PROJECT_REVIEW_2026-09-19.md)
for the engineering checks and deferred work.
