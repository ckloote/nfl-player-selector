# NFL Player Selector 1.0.1

Released October 25, 2026. A bug-fix release: pool reports that name a player in a slot
his position does not fit now import cleanly instead of failing.

## What changed

- **Misplaced picks.** In 2026 week 6 an entrant submitted a WR as his RB. The pool ruled
  that the pick stands: it scores zero, and the player is spent for the season. 1.0.0 left
  the name unresolved instead, so the import exited with an error, the standings stayed
  provisional, and the pot share was withheld.
- The importer now handles this case. If a name has no match at the slot's position but
  exactly matches one player at another position, it records a **misplaced** pick. The pick:
  - is reported as a warning, not an error
  - scores a final zero straight away
  - counts as spent
  - shows as `Name (misplaced)` in `pool standings`
- A misspelled or partial name outside the slot still comes back unresolved, so a typo
  is never quietly scored as zero.
- Rival simulation and pot share treat a misplaced pick as an empty slot and keep the
  player out of that rival's remaining pool. It does not zero the player's week for anyone
  who picked him in a slot he fits. Grading the predictors skips it, so an entry mistake
  is not counted as a model miss.
- The ruling is now rule 7 in [`docs/DESIGN.md`](../DESIGN.md).

## Install and upgrade

Install or replace the uv tool installation with the release wheel:

```bash
uv tool install --force https://github.com/ckloote/nfl-player-selector/releases/download/v1.0.1/nfl_pool-1.0.1-py3-none-any.whl
```

For a source checkout, switch to tag `v1.0.1` and run `uv sync --locked`.

**This release includes a database migration.** Schema version 5 adds a `misplaced`
column to the reported picks, with a default of 0, and it runs automatically the first
time 1.0.1 opens the database. Back up the database before upgrading (`pool backup`).
Re-import any week whose report has a misplaced pick, so the pick is recorded with the
new flag. Nothing else needs re-importing. No runtime dependencies changed.

## Verification

As for 1.0.0, the release is gated by the lint, formatting and full pytest CI job, and by
the separate wheel-install job. The fix was also checked by re-importing the week 6
report against a copy of a live season database: the import exits 0, the standings are
final through week 6, and the pot share is computed.
